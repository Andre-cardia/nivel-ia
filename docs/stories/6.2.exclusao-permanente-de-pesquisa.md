## Story

**Como** administrador do Nível IA,
**quero** excluir permanentemente uma pesquisa e todos os seus dados associados,
**para que** eu possa remover dados de clientes que não devem mais permanecer no sistema.

## Origem e escopo aprovado

Solicitação direta do usuário em 2026-09-04: criar um botão de exclusão de pesquisa. Após a explicação de que o contrato atual apenas desvincularia os diagnósticos, o usuário definiu: “apagar tudo”.

O escopo é exclusivamente a exclusão permanente iniciada no Dashboard administrativo. Não inclui lixeira, restauração, exclusão em massa, alteração de permissões ou publicação em produção.

## Acceptance Criteria

- [x] AC-1: Cada card de pesquisa no Dashboard exibe a ação “Excluir”, visualmente distinta da ação “Ver detalhes”.
- [x] AC-2: A ação pede confirmação explícita e informa que a pesquisa, o link, os respondentes e todas as respostas serão apagados permanentemente; a quantidade de respondentes é exibida quando disponível.
- [x] AC-3: Ao confirmar, uma única operação transacional remove os `assessments` associados à pesquisa e, por cascata, seus `assessment_answers`, antes de remover a `survey`; nenhuma exclusão parcial é persistida em caso de falha.
- [x] AC-4: Apenas o papel autenticado pode invocar a operação; o navegador não recebe privilégios além das políticas existentes de administrador.
- [x] AC-5: Em êxito, o card é removido e os totais do Dashboard são recalculados; em falha, o card permanece e o erro é apresentado ao administrador.
- [x] AC-6: A chamada RPC e seus argumentos têm teste automatizado; `npm run lint`, `npm run typecheck`, `npm test` e `npm run build` são executados e registrados.

## Dev Notes

Não há PRD ou arquitetura configurados disponíveis em `docs/`; o escopo acima deriva da solicitação explícita do usuário. Os pontos abaixo são contratos existentes verificados no repositório.

- `src/pages/admin/Dashboard.jsx` lista `surveys`, calcula `respondent_count` a partir de `assessments` e é o ponto de inserção da ação.
- `supabase/migration_v2.sql`, seção “Adicionar colunas em assessments”, define `assessments.survey_id REFERENCES surveys(id) ON DELETE SET NULL`; portanto um `DELETE` simples da survey preservaria diagnósticos órfãos e não atende ao escopo aprovado.
- `supabase/schema.sql`, seção “Tabela de respostas por dimensão”, define `assessment_answers.assessment_id REFERENCES assessments(id) ON DELETE CASCADE`; apagar os `assessments` remove as respostas associadas.
- `supabase/migration_v2.sql`, seção “RLS para surveys”, e `supabase/migration_v4.sql` concedem o gerenciamento de surveys e a exclusão de assessments a administradores autenticados.
- A função deve usar `SECURITY INVOKER`, privilégio padrão recomendado para funções de banco, e a chamada cliente deve usar `supabase.rpc`. [Source: Supabase Database Functions and JavaScript RPC documentation]

### Requirements Traceability

- AC-1 e AC-2: `Dashboard.jsx` apresenta uma ação separada, confirma a empresa e informa que o link, os respondentes e as respostas serão removidos permanentemente.
- AC-3: `delete_survey_with_responses` exclui os assessments antes da survey dentro da mesma função; a FK existente de `assessment_answers` usa `ON DELETE CASCADE`.
- AC-4: a função usa `SECURITY INVOKER`, valida `auth.role()`, revoga execução de `PUBLIC` e a concede somente a `authenticated`.
- AC-5: o card sai do estado apenas após êxito da RPC; falhas preservam o card e exibem um alerta recuperável.
- AC-6: os testes verificam o nome/argumento da RPC e propagação da falha. Lint, typecheck, testes e build passaram.

### Security and Reliability Review

- Não há SQL interpolado no cliente; o UUID é fornecido como argumento nomeado à RPC.
- A exclusão é atômica no banco: qualquer erro em uma das operações aborta a função e reverte a transação.
- O cliente não exibe detalhes internos de erro. O erro bruto fica apenas no console local para diagnóstico.
- A operação permanece global para administradores autenticados, coerente com as políticas existentes de `surveys` e `assessments`; não foi introduzida elevação de privilégio.

### Test and Verification Evidence

- `npm run lint`, `npm run typecheck`, `npm test` (14/14) e `npm run build`: aprovados.
- `npm audit --audit-level=high`: aprovado, 0 vulnerabilidades.
- `git diff --check`: aprovado.
- CodeRabbit: indisponível neste ambiente macOS; não há configuração ativa em `core-config.yaml`. A revisão manual acima substituiu a etapa automatizada.
- Não foi possível executar smoke visual neste ambiente: `agent-browser` e um navegador CUA não estão disponíveis. A migração remota foi confirmada pelo usuário como aplicada; o smoke autenticado de exclusão deve ser feito após o deploy com uma pesquisa descartável.
